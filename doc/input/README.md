# 输入文档说明（doc/input）

本目录存放数据需求生成的输入文件。引擎读取 research brief，输出 Markdown 数据需求文档。

## 1. 推荐流程

```powershell
py -m engine.cli init                  # 从模板创建 doc/input/research_brief.md
# 编辑 research_brief.md
py -m engine.cli validate              # 查看解析结果与待确认项
py -m engine.cli generate              # 输出 doc/output/data_requirement.md
```

- 输入格式：Markdown（推荐）或 JSON。
- 编码：UTF-8（无 BOM 或有 BOM 均可）。
- 默认输入：`doc/input/research_brief.md`。
- 指定输入：`--input path/to/file.md`。

## 2. 文件结构

```markdown
---
project_name: 项目名称
target_population: 目标总体
...
---

<!-- 填写说明注释不会进入正文 -->

## 研究背景
...
## 研究问题
1. RQ1：...
```

- frontmatter 必须位于文件第一行 `---` 与下一个 `---` 之间。
- 正文按二级标题 `## 章节名` 切分；章节顺序不限。
- `<!-- ... -->` 注释会被忽略。
- 只有 frontmatter、没有正文也可以生成，但文档质量会下降。

## 3. frontmatter 字段

只支持**单行键值**和**行内列表**，不支持 YAML 嵌套、多行字符串或锚点。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `project_name` | 字符串 | 待确认 | 项目名称，进入文档标题。**建议必填** |
| `project_slug` | 字符串 | 空 | 英文短名，可用于文件命名 |
| `competition` | 字符串 | 正大杯全国大学生市场调查与分析大赛 | 赛事/项目类型 |
| `research_type` | 字符串 | 市场调查 | 市场调查、消费者研究、满意度调查等 |
| `industry` | 字符串 | 待确认 | 行业，如现制饮品、家电、文旅 |
| `region` | 字符串 | 待确认 | 研究区域，影响渠道与抽样框建议 |
| `target_population` | 字符串 | 待确认 | 目标总体，尽量写清地区、人群与时间范围 |
| `survey_unit` | 字符串 | 个人 | 调查单位：个人、家庭、企业、门店等 |
| `data_sources` | 行内列表 | 空 | 如 `[一手问卷, 公开文本/评论, 二手行业数据]` |
| `survey_mode` | 字符串 | 线上为主 | 线上为主、线下为主、线上线下结合 |
| `confidence_level` | 数值 | 0.95 | 置信水平，常用 0.90 / 0.95 / 0.99 |
| `margin_error` | 数值 | 0.05 | 允许误差（绝对值），如 0.05 表示 ±5% |
| `expected_proportion` | 数值 | 0.5 | 预估比例 P；无先验信息取 0.5 最保守 |
| `population_size` | 整数 | 空 | 有限总体规模 N；留空按无限总体处理 |
| `design_effect` | 数值 | 1.2 | 设计效应 deff；简单随机抽样为 1.0 |
| `response_rate` | 数值 | 0.9 | 预计有效回收率 r；用于计划发放量 |
| `budget_cny` | 整数 | 空 | 预算（元），影响渠道推荐 |
| `timeline_weeks` | 整数 | 空 | 调研周期（周） |
| `team_size` | 整数 | 空 | 团队人数，影响分工与执行建议 |

补充规则：

- 列表也支持 `data_sources: 一手问卷, 公开文本/评论`（逗号分隔）。
- 布尔值写 `true` / `false`；空值写 `待确认` 或留空。
- 字段缺失不会中断生成，但会在第 10 章“待确认事项”中列出。
- `margin_error` 大于 0.10、`response_rate` 小于 0.50 会触发警告。

## 4. 正文章节

### 4.1 章节别名

标题会做归一化（忽略空格、标点、大小写），以下写法均可识别：

| 内部字段 | 可用标题 |
| --- | --- |
| background | 研究背景、项目背景、背景、研究缘起、Background |
| research_questions | 研究问题、核心问题、研究议题、待回答的问题、Research Questions、RQs |
| objectives | 研究目标、研究目的、研究任务、Objectives、Goals |
| constructs | 调查内容、核心构念、研究变量、变量设计、构念、变量、Constructs、Variables |
| existing_hypotheses | 研究假设、已有假设、假设、Hypotheses |
| constraints | 约束条件、研究约束、条件限制、限制条件、Constraints |
| preferred_methods | 分析方法倾向、拟用方法、方法偏好、分析方法、Preferred Methods、Methods |
| notes | 补充说明、其他说明、备注、Notes |
| strata | 分层、配额、分层配额、抽样分层、Strata、Quotas |
| basic | 基本信息、项目信息、研究概况、Basic Info |

“基本信息”章节内可写 `键：值`，作为 frontmatter 的补充（不覆盖已有值）。

### 4.2 研究背景

150–300 字，说明行业背景、研究缺口与项目价值。引擎会用它判断数据上下文（是否涉及文本、二手数据、宏观环境等）。

### 4.3 研究问题

推荐格式：

```markdown
## 研究问题

1. RQ1：武汉市大学生的咖啡消费频率与客单价呈现怎样的特征？
2. RQ2：不同年级学生的消费频率是否存在显著差异？
3. RQ3：产品品质对购买意愿有何影响？
```

- 每条一行，支持 `1.`、`-`、`*` 列表。
- 编号可写 `RQ1：`、`RQ1.`、`RQ1 ` 或省略；省略时按顺序编号。
- 建议使用能体现分析意图的动词：描述、比较/差异、相关、影响、中介、调节、分群、评价。
- 问题类型由关键词推断，可用 `py -m engine.cli validate` 查看识别结果。
- 若没有“研究问题”章节，引擎会把“研究目标”当作研究问题。

### 4.4 研究目标

每条一个可检验、可交付的目标。缺失时会用研究问题代替。

### 4.5 核心构念（变量设计）

这是变量确定的主输入。使用 Markdown 表格，列名可用中文或英文：

```markdown
| 构念 | 角色 | 操作化定义 | 题项数 | 量表 | 测量层级 | 数据来源 | 维度 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 购买意愿 | 因变量 | 未来一个月购买或推荐的可能性 | 4 | 5 级李克特 | 连续 | 一手问卷 | 购买/推荐 | 核心结果 |
| 产品品质 | 自变量 | 对口感、用料、稳定性的评价 | 5 | 5 级李克特 | 连续 | 一手问卷 | 口感/用料/稳定性 |  |
| 月生活费 | 调节变量 | 每月可支配生活费区间 | 1 | 单选 | 定序 | 一手问卷 |  | 同时用于分组 |
```

列说明：

| 列 | 必填 | 取值 |
| --- | --- | --- |
| 构念 | 是 | 变量名称，建议 2–8 字 |
| 角色 | 是 | 因变量、自变量、中介变量、调节变量、控制变量、筛选变量、探索性变量 |
| 操作化定义 | 建议 | 说明“用什么题测量什么” |
| 题项数 | 建议 | 整数；量表题建议每个构念 ≥3 题 |
| 量表 | 建议 | 5 级李克特、7 级李克特、单选、多选、填空、排序等 |
| 测量层级 | 建议 | 定类、定序、连续、文本、多重响应 |
| 数据来源 | 建议 | 一手问卷、公开评论文本、二手行业数据、平台数据等 |
| 维度 | 可选 | 用 `/` 或 `、` 分隔子维度 |
| 备注 | 可选 | 特殊说明，如“同时作为分组变量” |

规则：

- 角色缺失时，引擎会根据列名和备注推断，但**必须人工复核**。
- 一个变量原则上只承担一个主角色；既是调节又用于分组时，在备注中说明。
- 量表题构念（李克特）会自动进入信度、效度与 SEM 的测量部分。
- 没有构念表时，引擎从研究问题中提取变量并推断角色，输出会标注“推断”。

### 4.6 分析方法倾向

```markdown
## 分析方法倾向

- 描述性统计
- 方差分析
- 多元线性回归
- 中介效应检验
- 文本情感分析
```

这是**偏好**而非强制。引擎会优先考虑，但仍检查样本量与前提；不适用时会在第 5 章说明原因。

### 4.7 约束条件

```markdown
## 约束条件

- 预算约 3000 元，以线上问卷为主。
- 周期 6 周，团队 5 人。
- 需要覆盖不同年级与专业。
- 公开评论只使用平台公开数据，不采集个人信息。
```

约束会影响渠道推荐、投放节奏、质控强度与风险提示。

### 4.8 分层配额

```markdown
## 分层配额

- 大一：25%
- 大二：25%
- 大三：25%
- 大四：25%
```

- 每行“层名：比例%”，比例合计建议为 100%（引擎会归一化）。
- 也支持人数，写成“层名：120人”（带“人”字，避免与百分比混淆）。
- 不要用 Markdown 表格写分层，表格不会被解析。
- 未填写时，文档会按性别、年级/年龄、地区给出建议配额。

### 4.9 补充说明

填写其他约束、已有二手资料、指导教师要求、工具偏好、伦理要求等。未知信息写“待确认”。

### 4.10 已有研究假设（可选）

如需保留团队已写好的假设，新增：

```markdown
## 研究假设

- H1：产品品质对购买意愿具有显著正向影响。
- H2：品牌信任在产品品质与购买意愿之间起中介作用。
```

- 每条一行；已有编号会被保留，引擎再统一重排。
- 提供该章节后，引擎不再自动从研究问题生成假设，只补齐变量、方法与理论绑定。
- 不需要时删除整个章节。

## 5. JSON 输入

适合由其他脚本生成输入。字段名与 frontmatter 一致，另支持：

```json
{
  "project_name": "大学生咖啡消费研究",
  "target_population": "武汉市高校在校大学生",
  "data_sources": ["一手问卷", "公开文本/评论"],
  "research_questions": [
    {"qid": "RQ1", "text": "大学生咖啡消费频率呈现怎样的特征？"},
    {"qid": "RQ2", "text": "不同年级学生的消费频率是否存在显著差异？"}
  ],
  "constructs": [
    {"name": "购买意愿", "role": "dependent", "items": 4, "scale": "5 级李克特", "measure": "连续"},
    {"name": "产品品质", "role": "independent", "items": 5, "scale": "5 级李克特", "measure": "连续"}
  ],
  "strata": [{"name": "大一", "ratio": 0.25}, {"name": "大二", "ratio": 0.25}],
  "preferred_methods": ["多元线性回归"],
  "constraints": ["预算 3000 元"]
}
```

- `research_questions` 可为字符串数组或 `{qid, text}` 数组。
- `constructs` 的 `role` 用英文：dependent / independent / mediator / moderator / control / screening / exploratory。
- `strata` 使用 `ratio`（0–1）或 `count`。

## 6. 校验与排错

```powershell
py -m engine.cli validate -i doc/input/research_brief.md
```

输出会列出：项目名称、研究类型、目标总体、研究问题及识别类型、构念数量、数据来源、校验问题。

常见问题：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 研究问题识别为“描述” | 问题缺少分析动词 | 加入“差异/影响/关系/中介/调节”等词 |
| 变量角色全部为“推断” | 未填构念表或角色列 | 补全核心构念表 |
| 分层配额未生效 | 使用了表格 | 改为 `- 层名：25%` 列表 |
| 样本量异常小 | 允许误差过大或有效率过低 | 检查 `margin_error`、`response_rate` |
| 中文乱码 | 文件不是 UTF-8 | 另存为 UTF-8 |

## 7. 文件命名建议

- 正式输入：`research_brief.md`
- 示例/测试：`example_research_brief.md`
- 多方案对比：`research_brief_方案A.md`、`research_brief_方案B.md`
- 输出按项目命名：`doc/output/<project_slug>_data_requirement.md`
