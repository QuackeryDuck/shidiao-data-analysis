# 数据需求文档生成

把研究想法变成可执行的数据设计：变量怎么定、样本要多少、每个研究问题用什么模型、检验什么假设、数据从哪来、如何质控。核心是在收数据之前定清分析路径，避免后续返工。

## 何时使用

- 做市场调查、消费者研究、满意度/需求/品牌研究、正大杯等竞赛项目。
- 需要变量设计、样本量、抽样配额、问卷题项规划、模型选择、假设、渠道或质控方案。
- 已有一份研究简介、开题报告或问卷草稿，想知道“数据怎么设计”。

不用于：单纯跑统计检验、写文献综述、生成问卷全文、分析已收好的数据。只问“这组变量用什么模型”时，使用独立的 `model-match` skill。

## 工作流

### 1. 定位项目与输入

项目根是同时包含 `engine/cli.py` 与 `doc/input/` 的目录。按以下顺序查找：

1. 环境变量 `DATA_REQUIREMENT_PROJECT_ROOT`。
2. 从当前工作目录向上逐级查找。
3. 从本 skill 目录向上查找（上两级）。

找不到时询问用户路径，不要凭空创建 `engine/`。默认输入为 `doc/input/research_brief.md`，也接受其他 `.md` 或 `.json`。没有现成文件时，复制 `doc/input/research_brief.template.md` 后再填写。

先读取并提取：项目名称、目标总体、调查方式、样本参数、研究问题、核心构念、方法偏好、约束、配额、已有假设。最低可用输入是“项目名称 + 研究问题”。信息不足时不要反复追问：用合理默认值生成，并在第 10 章列出待确认项。

### 2. 校验与生成

```powershell
py <skill-dir>/scripts/run_engine.py validate -i doc/input/research_brief.md
py <skill-dir>/scripts/run_engine.py generate -i doc/input/research_brief.md -o doc/output/data_requirement.md
```

Windows 使用 `py`，不要使用可能指向占位程序的 `python`。`validate` 会显示每个 RQ 的类型、构念数与校验问题；先看这里，能提前发现模型错配。`generate` 输出文档与摘要：RQ、假设、变量、有效样本/计划发放、核心/可选模型、渠道、待确认项。需要单独核算样本量用 `sample`，查模型库用 `models`。

生成后先读第 0、2、3.1、4.3、5.3、5.4、6.1、7.1、10 章，这几处决定文档是否可用。

### 3. 复核

引擎负责结构与基线，你负责判断。按六项逐条检查：

| 部分 | 必须确认 |
| --- | --- |
| 研究问题与假设 | 每个 RQ 能落到假设或探索性问题；IV/DV/中介/调节一致；差异问题用分组变量；方向有依据；检验方法与第 5 章一致 |
| 变量 | 因变量确为结果变量；每个核心构念有定义、题项、量表、测量层级；控制变量有理由；变量字典能指导编码；无关键变量遗漏 |
| 样本 | 总体与抽样框可操作；公式、参数、结果一致；设计效应与有效率合理；配额合计 100%；每个核心模型样本门槛满足，否则有补样或降级方案 |
| 模型（重点） | 5.3 无 RQ—变量—模型错配；每个模型说明问题、理由、数据、前提、结果解读、备选；核心模型 6–12 个（纯问卷 6–10）；高阶模型有降级方案 |
| 渠道与质控 | 渠道能触达目标总体；配额与渠道能力匹配；无效问卷规则可执行；质控责任到人；文本/二手数据合规 |
| 交付 | 六项齐全且有实质内容；第 10 章如实披露默认值与推断项；不编造文献、数据、结果或平台政策 |

补写时保持原结构：优先补 5.4 各模型的“在本题中的定位”、第 6 章渠道执行、第 7 章质控清单和第 10 章待确认事项。

### 4. 交付

报告：输出路径；RQ/假设/变量数；n0、有效样本、计划发放；核心模型及一句话理由；渠道组合；仍需确认的事项；并说明“这是研究设计基线，不含统计结果，不能直接作为参赛终稿”。

不要声称已完成数据收集、信效度检验或显著性检验——这些需要真实数据。

## 质量门槛

- 六个必需部分齐全，每部分有实质内容。
- 每个核心模型可追溯到一个 RQ 和一组变量。
- 样本量公式、参数、结果一致，敏感性分析可解释。
- 假设表的方法与第 5 章一致。
- 渠道、预算、周期与目标总体不矛盾。
- 质控覆盖设计、抽样、执行、清洗、分析、交付六阶段。
- 第 10 章披露所有默认值与推断项。
- 不编造文献、数据、统计结果或平台政策。

## 参考文件

- `references/quick_reference.md`：输入字段、输出章节、模型速查、样本门槛、复核清单与常见错配。需要查格式或解释模型时读。
- `scripts/run_engine.py`：自动定位项目根并调用引擎。

## 常见失败与纠正

| 失败 | 纠正 |
| --- | --- |
| 只看 RQ 关键词，不读构念表 | 以构念表为准，关键词只作补充 |
| 所有 RQ 推荐同一组模型 | 逐题检查 5.3，删除无 RQ 支撑的模型 |
| 样本量只给一个数 | 保留公式、参数、敏感性与门槛校验 |
| 假设与模型各写一套 | 以假设表的检验方法回改第 5 章 |
| 渠道只列平台名称 | 补触达方式、配额、成本、质控与合规 |
| 把推断项藏起来 | 全部写入第 10 章并口头提示 |

## 边界

- 本 skill 生成研究设计，不执行统计计算，不替代真实数据。
- 模型推荐偏本科竞赛可执行性，不追求方法前沿。
- 自动识别有误差；重要取舍要说明依据与不确定性。
- 公开文本与二手数据必须合规使用，不协助绕过平台限制或采集个人信息。
