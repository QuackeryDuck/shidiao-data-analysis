# 输出规范（数据需求文档）

生成文件默认 `doc/output/data_requirement.md`，UTF-8 Markdown，固定章节编号。

## 1. 必须包含的六项

| 要求 | 章节 | 判定标准 |
| --- | --- | --- |
| 变量确定 | 第 3 章 | 有角色、操作化定义、测量层级、题项、变量字典，且变量—模型有映射 |
| 样本参数 | 第 4 章 | 有公式、参数值、计算结果、有限总体修正、设计效应、有效率、配额、敏感性 |
| 模型方法（重点） | 第 5 章 | 每个 RQ 有主模型；每个模型有适用理由、变量、前提、结果解读、备选 |
| 假设 | 第 2 章 | 假设可检验，含 IV/DV/中介/调节、方向、检验方法、理论依据 |
| 调查渠道 | 第 6 章 | 有主/辅/备渠道、触达方式、配额、成本、节奏、合规 |
| 质控措施 | 第 7 章 | 覆盖设计、抽样、执行、清洗、分析、交付六阶段，规则可执行 |

六项缺一不可。只有标题没有实质内容视为未完成。

## 2. 章节规范

### 第 0 章 文档摘要

一页纸：研究目的、目标总体、样本量、核心变量、核心模型、数据来源、主要交付物。读者应能在 2 分钟内理解研究设计。

### 第 1 章 研究概述

1.1 背景；1.2 研究问题（编号 + 原文 + 类型）；1.3 目标；1.4 范围与调查单位；1.5 概念框架（Mermaid）；1.6 数据需求总览。

概念框架要求：

- 方框为构念，箭头为关系；
- 自变量 → 因变量为主路径；
- 中介在路径中间，调节指向路径或交互项；
- 分组比较用虚线标注，不要画成因果箭头；
- 控制变量可单列在下方，避免主图拥挤。

### 第 2 章 研究假设

- 2.1 假设表：编号、假设原文、类型、对应 RQ、IV、DV、中介/调节、方向、检验方法。
- 2.2 每条假设的说明：理论依据、变量测量、检验口径、判定标准。
- 2.3 无法转化为假设的探索性问题及原因。

假设写法：

- 差异：`不同{分组}的受访者在{结果}上存在显著差异。`
- 关联：`{A}与{B}之间存在显著相关关系。`
- 影响：`{X}对{Y}具有显著{正向/负向}影响。`
- 中介：`{M}在{X}与{Y}之间起中介作用。`
- 调节：`{W}调节{X}对{Y}的影响。`

方向词必须有理论或文献依据；没有依据写“待检验”，不要臆造正负。

### 第 3 章 变量确定

- 3.1 总览：角色、名称、测量层级、题项数、来源。
- 3.2–3.6 按角色展开：因变量、自变量、中介/调节、控制、筛选与质控。
- 3.7 变量字典：字段名、题号、含义、类型、取值/编码、缺失编码。
- 3.8 量表与题项设计：维度、题项、计分方式、反向题。
- 3.9 问卷结构：模块、题号、题型、对应变量、质控题。
- 3.10 变量—模型映射：每个变量被哪些模型使用。

变量字典是问卷编码与数据清洗的共同依据，字段名应与数据集一致。

### 第 4 章 样本与抽样

- 4.1 目标总体、抽样框、调查单位、时间范围。
- 4.2 抽样方法：概率/非概率、分层/多阶段、实施步骤。
- 4.3 样本量：公式、参数、n0、有限总体修正、设计效应、有效率、计划发放。
- 4.4 敏感性分析：置信水平 × 允许误差的变化。
- 4.5 分层配额：层、比例、目标样本、渠道。
- 4.6 模型样本门槛校验：模型、最低样本、当前样本、是否满足、建议。
- 4.7 数据来源与采集规模：问卷、文本、二手数据。

公式统一写作：

```text
n0 = z² · P(1−P) / d²
n0' = n0 / [1 + (n0 − 1) / N]        （有限总体）
n_eff = n0' · deff
n_plan = ceil(n_eff / r)
```

### 第 5 章 模型与方法（重点）

- 5.1 选择逻辑：从 RQ 类型 → 变量层级 → 样本 → 前提 → 团队能力。
- 5.2 方法路线图：按分析阶段排列（描述 → 测量 → 推断 → 机制 → 文本 → 策略）。
- 5.3 RQ—变量—模型对应表：每个 RQ 的主模型、辅助模型、涉及变量。
- 5.4 核心模型详解，每个模型包含：
  1. 在本题中的定位；
  2. 对应研究问题与涉及变量；
  3. 为什么选它（变量层级、样本、理论）；
  4. 核心公式或计算口径；
  5. 分析步骤；
  6. 前提与检验；
  7. 结果解读；
  8. 备选方案；
  9. 软件与代码建议（可选）。
- 5.5 前提检验清单：检验项、方法、判定标准、不满足时。
- 5.6 稳健性与备选方案。
- 5.7 软件与代码模块建议。

模型条目必须能回答“为什么是这个模型，而不是另一个”。

### 第 6 章 调查渠道

- 6.1 渠道组合：主渠道、辅助渠道、补充渠道、备用渠道。
- 6.2 执行表：渠道、触达方式、目标样本、成本、负责人、时间。
- 6.3 二手数据与文本来源：来源、用途、获取方式、合规。
- 6.4 各渠道质控与合规要点。
- 6.5 投放节奏：预热、正式、补样、截止。
- 6.6 合规要求：知情同意、隐私、平台条款、数据存储。

渠道建议必须能落地：说清“在哪里找到谁、怎么发、发多少、谁负责”。

### 第 7 章 质量控制措施

- 7.1 六阶段总览：设计、抽样、执行、清洗、分析、交付。
- 7.2–7.5 各阶段规则：检查项、标准、责任人、记录。
- 7.6 伦理与数据安全。
- 7.7 质控清单：可勾选。
- 7.8 验收标准：有效样本、完成率、逻辑错误率、信度下限、缺失率上限。

无效问卷规则要可执行，例如：

- 作答时长 < 中位数 1/3；
- 直线作答连续 ≥ 8 题；
- 反向题与正向题矛盾；
- 甄别题错误；
- 逻辑矛盾（如“从不喝咖啡”但填写了品牌偏好）；
- IP/设备/微信号重复。

### 第 8 章 数据交付

数据集结构、字段命名、编码、缺失值、异常值、版本命名、交付清单。

### 第 9 章 进度、分工与风险

周计划、角色分工、风险登记与应对。

### 第 10 章 待确认事项

列出：

- 引擎使用的默认值；
- 从研究问题推断的变量与角色；
- 需要团队确认的假设；
- 受输入限制无法判断的事项。

这一章是诚实披露，不是免责声明。每条都应说明“为什么不确定”和“建议怎么确认”。

### 附录

- A：本研究相关模型速查（名称、用途、样本、前提）。
- B：方法学参考文献（正式提交前按学校格式补充）。
- C：术语表。

## 3. 格式规范

- 标题层级：`#` 文档标题；`##` 章；`###` 节；`####` 模型。
- 表格使用 GitHub Markdown；长文本列放最后。
- 数字：样本量取整；百分比 1 位小数；统计量保留 2–3 位小数。
- 公式：行内用反引号；独立公式用代码块。
- 概念框架用 Mermaid `flowchart`，确保在 GitHub/Typora/VS Code 可渲染。
- 不写“可能”“大概”“建议考虑”等模糊词；不确定就写“待确认”并给出确认方式。
- 不编造文献、数据、统计结果、平台政策或样本量依据。
